Lumi @-handle bar

Type @ in the bar — saved handles paint instantly as a head start, then the real search refines them: Local DB → remembered → cached (fresh for 60 min) → Xpoz live (budget-guarded, stale cache re-queries in real time). Pick the platforms in the selector — X, Instagram, TikTok, Reddit search live (2 / 12 / 5 / 2 credits per query, shown on each pill), LinkedIn has no live provider here and answers from saved handles only (never invented). The DB adds to results, never replaces them — only a fresh cached search can skip live for that platform. A db miss breathes until the actual people arrive. Every pulled handle, with picture, name and followers, is saved. The list is a half-and-half mix by where each handle came from on this search: about half the slots go to the saved half — everything served from memory (Local DB, remembered, cache), with local-DB handles like @AtehOfficial leading it — and half to the live half, what the fresh Xpoz pull just returned (a side that runs short hands its leftovers to the other so the list still fills to ten), with the exact handle you typed kept at the top.

Selection is remembered server-side (POST /api/handles/select) and reused by the next search — that's the cross-platform handle-mapping seed. Wiring into the main chat is deliberately out of MVP scope.
